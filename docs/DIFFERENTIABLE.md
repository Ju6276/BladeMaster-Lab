# 可微分 BladeMaster：状态与后续计划

2026-11-01：原 E4/E5 持续目标已删除，新目标已启动：统一方法和版本，验收完整自然单刀切割，完成刀路优化。当前归并第 1 步的统一版本，并执行第 2 步完整任务；采用初始刚性内聚断裂与独立几何接触。

## 交付目标

实现可信、通用的 BladeMaster 可微分版本：粒子形变、塑性、接触历史、切割事件和刀路共同参与求导。自然切割从未切割初态出发，每次扰动重新生成切口与接触；损伤历史、旧切口和切后重新接触进入同一状态推进与检查点流程。

分别交付梯度正确性、步长/网格收敛、能量收支和刀路优化证据。自由刚体刀、位姿伺服、牛顿黏性与机器人双向耦合列入完整功能覆盖；Maxwell 黏弹性、真机标定和显示修补另行安排。

## 当前持续目标

在 RTX 4090 上统一版本和方法，完成从未切割状态出发的单刀切透、退刀与重新接触，并交付刀路/材料梯度、检查点、能量、步长趋势及一次自然切割优化的完整证据。对应下列第 1–3 步；第 4 步继续承担通用性与原求解器功能覆盖。

### 1. 统一版本与确定方法

- 对照基线、本地 review 工作树和 4090 各候选，按功能整理差异、测试命令和已知失败；保存源码后再做取舍。
- 用原释放规则的闭合路径功与释放轨迹复现能量问题，区分实现错误和模型定义。
- 已复现固定损伤下的非零闭合路径功，并用解析、AD 和有限差分确认释放后力的交叉导数不对称。修复需要改变力学关系；单独补记损伤功或提高精度不能消除此项。
- 方法采用保留几何分侧、在线生成参考切面的初始刚性内聚模型，普通接触独立处理。局部接触势能修复与内聚的比较结果见 RESULTS，参数和来源见 METHOD。
- 按所选方法归并必要代码与已修复项，保留唯一正式入口，移除被替代实现；定位该路径的失败和异常结束原因。
- 高精度独立参考用于定位舍入与病态约束；正式求解的精度要求由误差传播、物理量与优化目标共同确定。采用原方程残差、无量纲缩放和收敛曲线检查修复。

归并顺序：状态/闭合反向修复 → 内聚与法向接触分离 → 有限刀具和空间接触 → 在线切面出生与事件分段。每组检查已有解析与自然差分，再由第 2 步检查完整任务。

完成条件：源码与结果可对应到干净提交；正式模型、参数含义、事件导数语义和唯一推进入口明确；全量测试通过。

### 2. 闭合完整自然切割任务

- 从完整方块开始，使用有限刀具完成下刀、切透、退刀和切面再接触；材料、接触、切面与计功共用同一状态推进。
- 改变刀位、行程、材料及历史，每次自然重建切面和接触，比较多档有限差分、完整反向与检查点反向。
- 同时做静置、无切割压入和切割的整体能量检查；覆盖损伤不活跃和活跃两类工况。
- 固定接触刚度和单位时间耗散率，缩小时间步，比较状态、力/功、事件时刻与梯度。
- 换一种形状或刀路重复关键检查。

完成条件：同一入口完成上述流程；梯度、能量和步长趋势都有通过结果；失败有明确根因和已复测的修复。

### 3. 先验证梯度能用于优化

- 优化连续刀路控制量，目标包含切后位置/形变及刀力；分离和切透作为独立任务检查。
- 目标、初值和预算在比较前固定。AD、FD 与 CMA-ES 使用相同五组初始化和墙钟预算，预算由预热后的实际梯度耗时确定。
- 记录初始/最终目标、成功率、评估次数、耗时、显存和力/功；所有最优刀路由同一模型无梯度自然重放。
- 对失败分开检查梯度错误、真实事件不光滑、参数化和预算；保留失败样本，修复后重测。

完成条件：自然切割优化达到预先定义的任务条件，并报告与基线的完整结果；短推压成功数作为已有对照。

### 4. 后续目标：扩展与完整功能覆盖

- 在统一版本复验暂停续切、平行/交叉多刀、推块及永久历史。
- 固定几何、材料和物理接触参数，完成空间细化；分别记录力、状态、能量和梯度的网格趋势。
- 更换材料、形状、刀路和采样，检查相同算法的泛化。
- 接入牛顿黏性及自由刀/位姿伺服/机器人状态的双向求导，核对耗散、动量、耦合步长和控制梯度。
- 补齐密度、泊松比、锋利度和几何参数的梯度接口，逐项明确可优化的输入及对应测试。

完成条件：自然切割验收与原 BladeMaster 功能覆盖分别有结果；最终交付使用同一已提交代码，全量测试通过，工作区干净。

## 验收约定

- 梯度对照评估同一个正向模型。保留已有实验的扰动档位和判据，至少两个相邻有效扰动尺度通过；同时报告绝对误差、相对误差及事件变化。真实切换边界检查单侧导数与事件序列。
- 固定分支导数、事件时间导数和软代理梯度分别命名；模型或导数定义的变更写入 METHOD。软代理方案若用于对照，优化后仍用目标正向模型重放。
- 检查点核对连续状态、侧码、接触 ID、损伤和事件时间。检查点一致与自然差分分别验收。
- 能量检查使用外功、动能/储能变化、物理耗散与数值残差的独立账本；解析小例与步长趋势配合判断。
- 测试通过数量按版本和范围记录。旧提交结果、候选模块结果与最终任务结果分别归档。
- 失败后定位和修复原因；公式修改、存储/调度修改分别提交，并复验受影响项。提交前运行 `PYTHONPATH=. .venv/bin/python -m pytest tests -q`。
